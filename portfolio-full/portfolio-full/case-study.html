Triaging traffic decay across 30,000+ content pages

Replacing an arbitrary manual review process with a model that ranks pages by real decay risk.

the problem

Manual review doesn't scale past a few hundred pages

At 30,000+ live content pages, deciding which ones are actually losing traffic — and need attention first — was being done by spot-checking and gut feel. That works at small scale and breaks completely at this one: real decay gets missed, and review time gets spent on pages that were never at risk.

the ML framing

Turn "which pages are decaying" into a ranked, scoreable problem

The task was reframed as a supervised triage problem: given a page's traffic history and content signals, predict a decay-risk score that ranks pages for review — instead of a binary rule that either flags a page or doesn't.

Before any model, the data itself needed a contract: what fields are guaranteed to exist, what their valid ranges are, what counts as a broken record. That schema-assertion step (see the code sandbox) is what made the baseline trustworthy enough to compare against.

the outcome

A baseline that beats the manual rule — with numbers, not a claim

The model's baseline precision on flagged pages beats the arbitrary manual-check rule (full comparison table in the code sandbox). That means fewer false flags eating review time, and fewer real decay cases slipping through unreviewed.
